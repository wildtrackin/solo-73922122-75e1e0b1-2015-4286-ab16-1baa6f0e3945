防火墙变更上线前检查

精确对比新旧规则，找出新规则意外放开的流量 · 首条匹配生效，未匹配默认拒绝 · 全地址/端口空间精确判定（非抽样）

规则格式与判定方法说明（点击展开）

每侧规则集是一个 JSON 数组（最多 30 条），规则按顺序匹配，首条命中生效；未命中任何规则的流量默认拒绝。每条规则是一个 JSON 对象：

字段含义取值
src源地址IPv4 CIDR，如 "10.0.0.0/8"；单主机可写 "10.0.0.1"（等同 /32）；"0.0.0.0/0" 表示任意
dst目的地址同上
proto协议"tcp" 或 "udp"（不区分大小写）
ports目的端口闭区间[下界, 上界]，如 [80, 443]；单端口可写 [80, 80] 或 80；范围 0–65535
action动作"allow" 或 "deny"
comment备注（可选）字符串

示例：

[{"src":"0.0.0.0/0","dst":"10.0.0.10/32","proto":"tcp","ports":[443,443],"action":"allow","comment":"HTTPS"}]

判定方法：把每条规则看作 (源IP, 目的IP, 端口) 空间中的长方体，TCP/UDP 分别对新旧规则集做精确的 长方体差集运算，覆盖全部 2³² × 2³² × 65536 × 2 种组合，不使用抽样。对每条新 allow 规则， 在其“实际生效区域”（扣除顺序在前的规则遮蔽）中检查是否存在被旧规则（含默认拒绝）拒绝的流量； 多条规则联合覆盖、规则顺序变化均被正确处理。若存在，给出一个具体的 witness（源/目的 IP、协议、端口） 及该流量在新旧两侧各自命中的规则。
